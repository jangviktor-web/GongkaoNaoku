## 为什么不是直接刷题

行测真题的难点从来不是"没做过"，而是**做过的第 8 天就忘了**。本应用的核心不是题库，而是那套排程：

- 每道题有独立的记忆状态（间隔、难度系数、复习次数、上次结果）
- 到点才推给你，不到点绝不打扰
- **答错或忘记的题会自动缩短间隔**，反复出现直到稳住
- 你只需做一件事：答完自评"我记住了多少"

题库只是载体，真正的产品是**复习的那条时间线**。

## 每道题都带什么

不是只有题干和答案。解析由程序从原始题库逐题抽取，每道题包含：

`问法模型` · `推理链` · `⚡最快解法` · `⚠易错点` · `🧩母题抽象` · `给定材料` · `官方解析` · `❓疑点待复核` · `📝个人笔记` · `⭐收藏`

## 记忆引擎：SM-2 怎么运作

作答后按真实记忆强度自评四档，系统据此重算这道题的**下次出现时间**：

| 自评 | 含义 | 引擎行为 |
| :--- | :--- | :--- |
| **忘记** | 完全没印象 | 今天重来，退回学习期 |
| **困难** | 想起来了但很吃力 | 间隔缩短，难度系数下调 |
| **一般** | 正常记住 | 标准间隔增长（1 → 6 → ×难度系数…） |
| **熟悉** | 轻松秒答 | 间隔拉长，难度系数上调 |

**键盘流**：作答时 `A/B/C/D` 选选项，`空格` 看标注；自评 `1/2/3/4` 对应 忘记/困难/一般/熟悉。

## 多账号与隐私

服务端按账号隔离数据，一套部署可多人使用，互不可见。

| 身份 | 说明 |
| :--- | :--- |
| **注册账号** | 用户名 + 密码登录（PBKDF2-HMAC-SHA256 加盐哈希），凭账号在任何设备续上进度 |
| **游客模式** | 免注册进入，自动获得一个云端匿名身份；**换浏览器或清缓存即为全新身份**。设置页可随时升级为正式账号，数据不丢；退出即销毁，不留残留 |

题量与进度都存放在服务端 SQLite，浏览器只保存一枚登录令牌。

## 常见问题

**换浏览器后进度不见了？**
注册账号后用用户名登录即可续上。游客模式的身份绑定在浏览器本地，换设备即为新身份——这是设计如此，不是丢数据。

**能不能多人共用？**
可以。各自注册账号，学习进度、笔记、收藏完全隔离，互相看不到对方的存在。

**占多大地方？**
代码不到 200KB。题库数据库（216MB，30MB×8 分卷）与配图（199MB）随仓库提供，**`git clone` 全部到手**，克隆后跑一次 `python3 assemble_db.py` 合并数据库即可，无需自备题库。

**需要联网吗？**
完全不需要。零第三方依赖、零 CDN、零外部字体，断网照常用。

**上游题库 58,890 题，为什么这里只有 27,506 题？**
上游的 58,890 是「题目行数」——联考同一道题会以几十个省卷的名义重复收录（平均每题 2.32 套卷，最多一道被 778 套卷收录）；按题去重后上游只有 25,382 道不同的题，本项目覆盖其中 25,271 道（**99.56%**），另有 158 道上游没有的更早年真题。不是漏题，是把「卷 × 题」去重成了「题」，更适合刷题与复习。逐题核查数据见 [题量差异说明](#素材来源与致谢)。

## 部署到 WorkBuddy 在线应用（无需本机安装）

本项目除了在本地跑，还可以一键部署为 **WorkBuddy 在线应用**：部署后获得一个独立公开网址，同学、研友浏览器打开即用——**不必人人装 Python、不必各自拷题库**，所有学习数据存服务端按账号隔离。

以下步骤为本项目**实际部署过程**的完整还原，全程只需要对 WorkBuddy 的 AI 助手「说人话」。

### 部署步骤

**① 准备**
打开 [WorkBuddy](https://www.workbuddy.ai)，新建一个 AI 会话（项目）。沙箱工作区自带 Python 3.11 和 git，无需配置环境。

**② 把代码放进工作区**

对助手说：

> 帮我克隆这个仓库到工作区：`git clone https://gitee.com/jangviktor/GongkaoNaoku.git /workspace/kaogong-webapp`

也可以把仓库打包成 zip 直接上传（仓库含 200MB 题库数据，克隆/上传需几分钟，耐心等它跑完）。

**③ 合并题库**

> 运行 `python3 assemble_db.py`，把分卷合并成 kaogong.db

约 10 秒完成，出现「27,506 题」的提示即成功。

**④ 本地试运行**

> 运行 `python3 server.py`，然后预览页面

WorkBuddy 内置浏览器预览，可以先自己刷几题确认一切正常。

**⑤ 发布为在线应用**

> 把 /workspace/kaogong-webapp 发布为应用，启动命令用 `PORT=$PORT python3 server.py`

发布动作会弹出一次确认，确认后你会得到一个形如 `https://xxxx.app.workbuddy.host` 的**公开访问链接**。

**⑥ 分享使用**

把链接发给任何人：打开即见登录页，**注册自己的账号**（换设备也能接着学）或点「游客模式」直接开刷。每个账号的学习进度、错题本、笔记相互隔离，互不可见。

**⑦ 日常更新**

题库或代码有更新时，在工作区 `git pull` 拉最新版，再执行一次发布即可覆盖线上版本（链接不变）。

<summary><b>📌 为什么上游 58,890 题，这里只有 27,506 题？（逐题核查报告，打消"漏题"疑虑）</b></summary>

<br>

**一句话结论：不是漏了题，是两种计数口径。** 上游的 58,890 是「题目行数」——一道题出现在几套卷里就计几次；本项目的 27,506 是「去重后的题目数」。我们把上游仓库全部 2,956 份试卷、58,890 行题目逐题解析，与本地 27,506 题逐条比对（题干 + 配图 + 选项 + 材料四重指纹），账目如下：

| 核查口径 | 上游 xingcezhenti | 本项目 考公脑库 |
| :--- | --: | --: |
| 标称题量（题目行，含跨卷重复收录） | 58,890 | 27,506 |
| **按题目去重后（不同题的道数）** | **25,382** | **25,429** |
| 两边都有的同一道题 | — | 25,271 |
| **上游有、本项目缺** | — | **111 道（占上游 0.44%）** |
| 本项目有、上游没有 | — | 158 道（2008–2015 更早年真题等） |
| **对上游唯一题的覆盖率** | — | **99.56%** |

**58,890 的"水分"有多大？** 公考真题大量来自多省同日联考——同一套题会以几十个省份的名义各自成卷、反复收录：

- 平均每道题被 **2.32 套卷**收录；
- 被 5 套以上卷子收录的 2,870 道题，单独贡献了 28,135 行——**占 58,890 的近一半**；
- 最极端的一道通用问法题，被 **778 套卷**收录。

真实例子：2019 年 420 联考的同一道片段阅读题，在上游以 20 多个省份卷的名义各计一次；本项目只保留 1 道，并保留可溯源的试卷信息。

**那 111 道缺口是什么？** 高度集中在天津（83）、河北（15）、广东（13）三地，且每道在上游都只被 1 套卷收录，属边缘题——资料分析 **100% 全覆盖**，判断推理、数量关系各缺 1 道，不影响任何模块的练习完整度。

**两种口径，各有各的用途：**

| | 上游（按卷收录） | 本项目（按题去重） |
| :--- | :--- | :--- |
| 题量 | 58,890 行 | 27,506 道 |
| 适合 | 在 Obsidian 里逐卷翻阅原卷、整卷模拟 | 不重复地刷题 + SM-2 间隔复习 |
| 同一道联考题 | 出现 20+ 次（每省卷一次） | 只出现 1 次，标记全部出处 |

> 验算：25,271（共有）+ 111（缺）= 25,382（上游唯一题）✓；25,271 + 158（本项目独有）= 25,429（本项目唯一题）✓。另外本地 27,506 行中有约 2,077 行是「题干文字相同、但配图或材料不同」的组题行（图形推理、资料分析的固有形态，不是重复），完全重复仅 5 行，已可忽略。
